## 简介

要将应用运行为 Windows 服务，最常见的工具是 NSSM、WinSW，以及现在的 Servy：

* NSSM：轻量但年代久远，仅提供基础的服务包装功能。
* WinSW：开源且基于 XML，在 Jenkins 中广泛使用，但维护不活跃，也缺少现代管理功能。
* Servy：开源替代方案，提供实时 GUI、完整的 CLI 与 PowerShell 模块、高级 `stdout`/`stderr` 日志轮转、自动健康恢复以及事件通知。

Servy 既满足高级用户对灵活性的期望，对偏好图形界面的用户也足够直观。它是运行和监控 Windows 服务的实用选择，并具备完整的管理与监控能力。

## 对比表

下表对比了 Servy、NSSM 与 WinSW。

**图例：** ✅ 完整支持 &nbsp;·&nbsp; ⚪ 部分 / 基础支持 &nbsp;·&nbsp; ❌ 不支持

| 功能 | Servy | NSSM | WinSW |
| -- | -- | -- | -- |
| GUI 管理 | ✅ 实时监控与配置 | ⚪ 基础安装程序 GUI | ❌ 无 GUI |
| CLI / 自动化 | ✅ 支持 PowerShell、CLI 与 CI/CD | ✅ CLI | ✅ 仅 CLI |
| 启动前/后钩子 | ✅ 高级，含重试与超时 | ❌ 不支持 | ⚪ 基础 |
| 停止前/后钩子 | ✅ 高级脉冲式清理 | ❌ 不支持 | ❌ 不支持 |
| 性能跟踪 | ✅ 实时 CPU 与内存图表 | ❌ 不支持 | ❌ 不支持 |
| CPU 亲和性 | ✅ 高级 | ❌ 不支持 | ❌ 不支持 |
| 服务账户 | ✅ 支持 System、域、AD 与 gMSA | ⚪ 有限 | ⚪ 有限 |
| 日志与轮转 | ✅ 高级按大小与按日期轮转 | ⚪ 基础 | ⚪ 基础 |
| 实时控制台预览 | ✅ 实时 stdout 与 stderr 流式输出 | ❌ 不支持 | ❌ 不支持 |
| 依赖预览 | ✅ 高级，含状态 | ❌ 不支持 | ❌ 不支持 |
| 进程树安全 | ✅ 优雅停止、Ctrl+C、强制终止 | ⚪ 基础 | ⚪ 基础 |
| 僵尸进程防护 | ✅ 递归进程树清理 | ❌ 不支持 | ❌ 不支持 |
| 健康与恢复 | ✅ 内置监控与自动重启 | ❌ 不支持 | ⚪ 有限 |
| 心跳 Ping URL | ✅ 带外 ping，支持 `/start` 与 `/fail` 标志 | ❌ 不支持 | ❌ 不支持 |
| 通知 | ✅ Windows 系统提醒与邮件 | ❌ 不支持 | ❌ 不支持 |
| 配置可移植性 | ✅ 导出与导入（XML/JSON） | ❌ 不支持 | ❌ 不支持 |
| 持续维护 | ✅ 是 | ❌ 否（不活跃） | ❌ 否（不活跃） |

Servy 面向需要可靠、可监控、可配置 Windows 服务的团队。它将 GUI、CLI、日志、通知与生命周期管理整合在一个工具中。NSSM 与 WinSW 仍适合轻量级服务包装，但无法提供同等水平的运维可见性与管理能力。

Servy 填补了这一空白，提供现代、免费、开源的替代方案，同时兼顾开发者与企业级功能。
